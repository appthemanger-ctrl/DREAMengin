\section{Purpose}
\textbf{DREAMengin} is a privacy-first, customizable homepage that pulls a creator's world into one calm feed --- widgets, promos, releases, links, music, games, and DMs --- with user choice and safety at the center. Core differentiators are private-by-default DMs, approval-based feeds, and explicit consent for any safety review of content. This document describes the user interface, information architecture, and end-to-end user experience across the \emph{Homepage}, \emph{Profile}, \emph{DMs}, \emph{AI (InnerDreams + Assistant)}, \emph{Music}, \emph{Shop}, \emph{Connectors}, and supporting flows (auth, theming, errors).

\section{Design Principles}
\begin{itemize}
  \item \textbf{Calm first.} Dark, low-contrast canvas with a subtle animated gradient; bright accents reserved for actions; no surprise recommendations or attention spam.
  \item \textbf{Composable.} Everything is a widget or block; order can be changed later without re-learning.
  \item \textbf{User-first privacy.} DMs and feeds are private by default; any AI scanning or human review is opt-in and triggered only by user reports or explicit actions.
  \item \textbf{Predictable.} Same surfaces for create, edit, delete, publish; identical empty-state patterns.
  \item \textbf{Mobile-first.} Thumb-friendly hit targets ($\geq$ 44\,pt), sticky primary actions, and safe scroll recovery.
  \item \textbf{Accessible.} Color contrast $\geq$ 4.5:1 for body; keyboard-only paths; ARIA for interactive widgets.
\end{itemize}

\section{Visual Language}
\subsection{Color \& Motion}
\begin{itemize}
  \item Background: \texttt{linear-gradient(120deg, brandB!80, brandA!70)} with 12--18\,s slow pan; no hue-flash on route change; respects \texttt{prefers-reduced-motion}.
  \item Text: slate/ink body; headings bold; links cyan. Success (green 500), danger (rose 500), warning (amber 500).
  \item Focus ring: 2\,px \texttt{brandA} outer ring + 1\,px black inner for WCAG visibility.
\end{itemize}

\subsection{Typography}
\begin{itemize}
  \item Display: \textbf{Space Grotesk} (or Sora) --- tight tracking for titles.
  \item Body/UI: \textbf{Inter}. Code/mono: \textbf{JetBrains Mono} (optional).
\end{itemize}

\subsection{Components (core kit)}
Buttons (primary, secondary, ghost), Inputs (text, password, email), Select, Textarea, Card, List, Tabs, Modal (Sheet on mobile), Toast, Avatar, Badge, Empty-state, Skeleton loader, Feed mode toggle, DM safety banner.

\section{Page UX}

\subsection{Landing (\texttt{/})}
\textbf{Goal:} fast orientation and conversion to account creation or entry.
\begin{itemize}
  \item Hero title: \emph{Dreampage --- your home on the internet}.
  \item Hero copy: ``Claim a private home feed, a public profile, and DMs where you decide what shows up and what can be reviewed.''
  \item CTAs: \textbf{Create account}, \textbf{Continue as guest}, secondary \textbf{Login}.
  \item Preview: A live theme tile demonstrating the gradient and typography.
  \item Footer: Links to Terms, Privacy, Changelog, and ``Privacy \& Safety'' explainer.
\end{itemize}

\subsection{Auth (\texttt{/signup}, \texttt{/login})}
\begin{itemize}
  \item Forms: email + password, with password rules; optional ``Send magic link''.
  \item Errors: show human-readable text; never dump raw tokens to the page.
  \item Success: redirect to \texttt{/home}. Persist session via Supabase SSR helpers.
  \item Post-login banner: ``Your DMs and drafts are private by default. You can turn safety scanning and human review on or off in Settings.''
\end{itemize}

\subsection{Homepage (\texttt{/home})}
\textbf{Goal:} personal feed made of widgets and connector items, with user-controlled visibility.
\begin{itemize}
  \item Sections: \emph{Your widgets}, \emph{Home feed}, \emph{Promos \& Releases}.
  \item Home feed: shows only sources and items the user has explicitly approved.
  \item Feed modes:
    \begin{itemize}
      \item \textbf{Strict} --- chronological, approved sources only, no ranking.
      \item \textbf{Algorithmic} --- ranked, user-toggleable, with visible ``why you're seeing this'' reasons.
    \end{itemize}
  \item Widget card: title, description, ``Move'', ``Hide'', and ``Config'' (kebab menu).
  \item Empty states guide first action (e.g., \emph{Add your first widget} or \emph{Connect a source}).
  \item Performance: dynamic rendering (no static export) to respect session and per-user data.
\end{itemize}

\subsection{Profile (\texttt{/profile/\{handle\}})}
\textbf{Public-facing page} with avatar, display name, links block, and a curated feed slice.
\begin{itemize}
  \item Layout: Header (avatar/name/handle), Link list (from \texttt{links\_json}), Latest items.
  \item Profile feed: curated slice of the user's content, limited to items explicitly marked ``Show on profile''.
  \item Visibility controls: per-block switches (Home-only vs Public) inside widget/post editors.
  \item SEO: title = ``\{Display Name\} --- DREAMengin'', description from profile bio; OpenGraph image from banner.
\end{itemize}

\subsection{DMs (private conversations)}
\begin{itemize}
  \item Threads: end-style private conversations; messages are not scanned or reviewed by default.
  \item Per-thread banner: ``Your messages here are private. Reports may be reviewed by our safety team, but reporters stay anonymous.''
  \item Reporting flow:
    \begin{itemize}
      \item Step 1: choose violation (harassment, hate, sexual content involving minors, spam, impersonation, other).
      \item Step 2: consent checkbox: ``I allow DREAMengin to review recent messages and media in this conversation for safety.''
      \item Step 3: confirmation screen with what may happen (mute, warning, restriction, ban) and link to appeals.
    \end{itemize}
  \item Review scope: only a bounded window (e.g., last 50--100 messages + media) is visible to safety reviewers per report.
  \item Reported user notice: generic alert that some messages were reported and which rule is under review; reporter identity is never shown.
  \item Reporter reputation: repeated clearly false reports affect an internal trust score and can lead to softer handling or temporary limits on reporting.
\end{itemize}

\subsection{Connectors (\texttt{/connectors})}
\begin{itemize}
  \item Each connector: card with status chip (\emph{Connected}/\emph{Needs auth}), \emph{Ingest now} button, last run time.
  \item Global action: \emph{Run all ingests}. Runs server-side tasks; shows toast summary.
\end{itemize}

\subsection{Music (\texttt{/music})}
\begin{itemize}
  \item Sections: Featured track, Playlists, Releases.
  \item Player widget supports cover art, play/pause, seek; falls back to external embeds if needed.
\end{itemize}

\subsection{Shop (\texttt{/shop}, \texttt{/shop/me})}
\begin{itemize}
  \item Shop: public grid of items; filter by type (digital, bundle).
  \item Me: creator dashboard (draft/published, price, fulfillment via Supabase Storage).
\end{itemize}

\subsection{Admin \& Ads (\texttt{/admin}, \texttt{/ads})}
\begin{itemize}
  \item Create promo: title, media, target routes, schedule; metrics table (views, clicks).
\end{itemize}

\section{AI Surfaces}

\subsection{Assistant API (\texttt{/api/assistant})}
\textbf{User-facing chat helper} (on-page coach).
\begin{itemize}
  \item Input dock with textarea and ``Send''.
  \item States: thinking (ellipsis), error (retry), and copy-to-clipboard for results.
  \item Privacy note: prompts are stored only if user opts in; Assistant never scans private DMs or drafts unless the user pastes or forwards them into the chat.
\end{itemize}

\subsection{InnerDreams (\texttt{/api/innerdreams/run})}
\textbf{Developer \& maintainer tool}. Summarizes build errors and proposes safe patches.
\begin{itemize}
  \item Output model: \texttt{\{ a: string, suggestions: string[] \}}; never writes without explicit user action.
  \item Scope: proposes code/config patches and content tweaks but does not auto-edit production.
\end{itemize}

\section{States \& Errors}
\begin{itemize}
  \item Loading: skeletons for cards/lists; avoid flashing empty content.
  \item Network errors: plain-language message and \emph{Try again}; log details server-side.
  \item Auth failures: ``Your email or password is incorrect''; throttle repeated attempts.
  \item Safety review pending: neutral banner on affected content or DMs (e.g., ``This content is under safety review.''), without implying guilt.
\end{itemize}

\section{Accessibility Checklist}
\begin{itemize}
  \item Labels and descriptions for all inputs; \texttt{aria-live=polite} on toast region.
  \item Keyboard order matches visual order; skip link to main content.
  \item \texttt{prefers-reduced-motion}: stop or slow gradient animation and heavy transitions.
\end{itemize}

\section{Personalization \& Theme}
\begin{itemize}
  \item Settings allow changing primary hue, font choice (Display/Body), density (Compact/Cozy), and background motion (On/Off).
  \item Theme and motion preferences apply to landing, auth, home, and profile so friends see a consistent Dreampage.
  \item Store preferences per user in \texttt{profiles}/\texttt{user\_settings} and apply on server for first-paint consistency, including feed mode and DM safety toggles.
\end{itemize}

\section{Analytics \& Events}
\begin{itemize}
  \item Minimal first-party events: \texttt{view\_page}, \texttt{click\_cta}, \texttt{play\_media}, \texttt{run\_ingest}.
  \item Store in Postgres via server actions; no third-party trackers by default.
\end{itemize}

\section{Key UX Copy}
\begin{itemize}
  \item Landing title: ``Dreampage --- your home on the internet''.
  \item CTA: ``Create account'' / ``Continue as guest'' / ``Login''.
  \item Empty homepage: ``Add your first widget or connect a source to see your world here.''
  \item DM banner: ``Your messages here are private. Reports may be reviewed by our safety team, but reporters stay anonymous.''
  \item Feed mode toggle: ``Strict feed (you approve everything)'' vs ``Algorithmic feed (ranked, with reasons).''
  \item Auth error: ``Authorization failed. Please sign in again.''
\end{itemize}

\section{Open Questions}
\begin{itemize}
  \item Connector OAuth scopes per platform and rate-limit policy.
  \item Release gating (email capture vs purchase) and payout flow.
  \item Multi-tenant admin for ad inventory across user profiles.
\end{itemize}
