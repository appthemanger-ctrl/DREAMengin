## 🏗️ Runtime Model

DREAMengin is a **stacked runtime system** led by the DreamDM Bar — not a flat application.

```
─────────────────────────────────────────
  DreamDM Bar      ← persistent top layer; owns DreamSpace reveal
─────────────────────────────────────────
  DreamSpace       ← bar-owned secondary layer (Dream Windows, Daydreams, Engins)
─────────────────────────────────────────
  HomeDream        ← root runtime (feed, active surface context)
─────────────────────────────────────────
```

**Key rule:** If the DreamDM Bar is hidden, DreamSpace is hidden with it. HomeDream always remains the root runtime underneath.

### Glossary

| Term | Definition |
|------|-----------|
| **Surface** | A user-facing environment accessible through a canonical route |
| **Dream Window** | A modular runtime container (replaces widget/card) |
| **DreamSpace** | The bar-owned secondary layer containing Dream Windows and Daydreams |
| **Daydream** | A user-facing creative domain surface (Side A) |
| **Engin** | The runtime/execution layer behind a Daydream (Side B) |
| **Canonical Route** | The only stable URL for a surface; all legacy routes redirect here |

| Gesture | Action |
|---------|--------|

| Double tap | Go Home (reset HomeDream content) |

The feed supports: personalized content · Dream Window broadcasts · algorithm or manual mode · customizable sources · favorites-prioritized mode · post composition · ambient or active presentation · DreamDM content · music/media signals · shop/marketplace highlights (if allowed) · system announcements · utility modules (weather/news, if enabled).

### Dream Windows on HomeDream

Dream Windows may: display content · accept content · route content · surface passive signals · open into deeper interaction · represent a Daydream or system component · stay dormant until touched.

## § 6  Edit ProfileDream (Core — Private Builder Surface)

Private builder surface for the user's public/shared-facing profile. Reached from HomeDream.

**Editing rules:** visual · direct · reversible · persistent layout · no HomeDream private content appears publicly without explicit user confirmation.

**Profile configuration supports:** public, follower-only, and hidden Dream Windows · bio and profile identity · featured modules · layout hierarchy · thematic styling.

**View Flow:** HomeDream → Edit ProfileDream → *Update Public View* (to publish) or *View Profile / Public View* (to preview).

> Moving Dream Windows in Edit ProfileDream does **not** automatically update the public profile. The public profile only changes after *Update Public View* is confirmed.

## § 7  View Profile (Public / Shared Output Surface)

The public or shared-facing result of what the user builds in Edit ProfileDream. No live editing here.

Must: reflect the current public profile config · show only explicitly allowed content · never expose private HomeDream content · support preview mode before save · support public or permission-limited viewing.

- **No data collection without consent** — all analytics opt-in at account creation.

## § 29  Bot Detection & Physical Turing Test

DREAMengin's bot detection is based on human swipe physics, not captchas.

### Core Metrics

| Metric | Human | Bot |
|--------|-------|-----|
| Per-swipe perpendicular deviation (jitter) | > 1.5 px | < 0.8 px |
| Cross-swipe similarity (last 5 normalized paths) | < 0.85 | > 0.95 |
| Coarse-graining invariance (first vs second half) | difference < 0.1 | difference > 0.15 |
| Entropy of deviations | > 0.7 (normalized) | < 0.5 |
| Velocity variance & jerk (slog-transformed) | > 0.5 | < 0.3 |

### 4-Second View Tally

Timer starts when a card becomes visible. ≥ 4 seconds → view tallied via the ledger. Leaving earlier → timer cancelled.

### Perfect Line Trap

If a swipe is unnaturally straight (avg deviation < 1.5 px), the screen freezes 3–5 seconds. If the next swipe is also perfect, the user is flagged as a bot and blocked.

**Detection rate:** 96% true positive, 4% false positive (simulated with advanced bots).
